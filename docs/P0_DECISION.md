# 黑白测评组官网｜P0 技术决策与开发计划

版本：P0-v1，2026-10-16（Asia/Shanghai）。状态：P0 交付，等待用户确认；P1 未开始。

需求基线：已完整读取《黑白测评组官网_Work开发交接规范_V1.md》全部 91 行。本地需求路径为 `docs/requirements/WORK_HANDOFF_V1.md`；原需求文件保持原身份，不覆盖、不改写。以下是技术落实方案，功能范围、视觉方向、非目标及审批边界继续以 V1 为准。

## 1. 决策摘要（一页取舍）

**选择独立全栈代码仓库作为正式产品；Work 用于开发，不把当前会话环境作为生产服务器。** Sites 的 D1、R2 和托管服务端能力是真实的平台能力，但当前提供的认证契约围绕 Sign in with ChatGPT；没有核实到邮箱密码注册、邮件验证、找回密码的原生实现契约。外接认证是否兼容尚未验证，不能替代 V1 已确定的账号系统。

V1 没有预先锁定框架。本次建议的唯一技术栈是 **Next.js App Router + TypeScript + Tailwind CSS，后端采用 Supabase Auth / PostgreSQL / Storage / Cron**。使用官方客户端、SQL 迁移、服务端权限校验和数据库行级权限；不增加独立 API 微服务、Redis、消息队列或自研密码系统。富文本使用成熟编辑器，具体包在 P2 按维护状态锁定，不扩大编辑功能。

| 比较项 | ChatGPT Sites | 独立仓库 + 建议技术栈 |
| --- | --- | --- |
| 邮箱密码与验证邮件 | 原生契约未核实；内置为 ChatGPT 身份 | Auth 官方支持；生产 SMTP 需另行配置与验收 |
| 数据、文件、业务权限 | D1、R2 支持；业务 RBAC 仍需开发 | PostgreSQL、Storage 与 RLS 支持；业务 RBAC 仍需开发 |
| 自动开奖 | 已提供关联云任务机制；未证明适合事务性开奖 | Cron 调用数据库函数；幂等与公平抽样由业务实现和测试保证 |
| 运维 | 托管方便，但认证及调度适配存在关键不确定性 | 托管后端减少运维；网站只保留一个应用进程 |
| 迁移 | 源码有 Git 工作流；数据、文件及身份迁移未演练 | Node.js/Docker 部署路径、PostgreSQL 迁移、可自托管后端；仍需迁移演练 |
| 本项目结论 | 暂不选作正式运行平台 | 推荐；用户确认 P0 后作为后续固定基线 |

生产级 SMTP、稳定运行的数据库和备份可能产生费用。**本轮不创建任何云项目、账号、定时任务或付费资源，不发送真实邮件，不部署。** 服务器、网站主机、域名、部署地区和 SMTP 商家继续暂缓；不把免费套餐承诺为正式上线方案。

## 2. 当前环境核查与证据等级

“文档支持”表示官方接口/本环境能力说明存在；“实测通过”必须有实际调用和持久化读回。本轮没有业务功能达到实测通过等级。

| 必需能力 | Sites 当前可确认的能力 | 未验证事项 / 本项目处理 |
| --- | --- | --- |
| 邮箱密码注册、登录 | 内置认证说明与 starter 均使用 ChatGPT 身份 | 邮箱密码原生能力未核实，外接兼容待验证；正式方案用 Supabase Auth |
| 邮件验证、找回密码 | 未提供项目自有验证/重置邮件的完整内置链路 | Supabase 文档支持；真实 SMTP 投递、回调、过期/重放测试留到 P2 |
| 角色权限 | 有站点访问控制及服务端用户身份；不等于玩家/发行商/编辑 RBAC | 本项目服务端和 RLS 均须实现；越权测试留到 P2/P3 |
| 持久化数据库 | Sites 文档明确提供 D1 与迁移 | 未创建 Site、未写入/读回；独立方案用 PostgreSQL，P2 验证重启及跨会话持久化 |
| 图片上传与展示 | Sites 文档明确提供 R2，服务端可访问 | 校验、私有权限、授权展示均未实测；独立方案用 Storage |
| 关闭网页后的自动开奖 | Sites 可关联云任务；创建要求已发布的本人 Site | 无确定时延/事务性开奖保证；不以提示词自动化作为开奖引擎。独立方案用数据库 Cron，P3 验证 |

环境实测：Node.js `v24.19.0`、npm `11.9.0`、Git `2.51.1` 可用；`SITES_MANAGED_LINUX_CONTAINER=1`。当前账号 Sites 列表为空；未初始化新 Site。未找到 Docker、psql；未连接项目后端或 SMTP；运行时公共模块目录中未发现 Next.js、React、Supabase JS、Playwright 测试包。没有执行依赖安装或网络可达性测试。

因此，Work 可承担代码与文档开发，但当前不能直接运行依赖 Docker 的本地 Supabase 全套环境。P1 先验证依赖安装与本地网页运行；P2 使用用户授权的隔离开发后端，或在具备 Docker 的开发机验证本地后端。不能声称当前 Work 已具备生产服务、完整离线开发后端或部署能力。

## 3. 简明架构与关键机制

| 层 | 责任与边界 |
| --- | --- |
| Next.js 单应用 | 中文/英文 UI、公开页、个人中心、发行商工作区、管理后台；Route Handlers/Server Actions 处理写入与业务校验。公开内容可缓存，个人/后台数据不得共享缓存 |
| Supabase Auth | 邮箱密码、验证邮件、重置密码及会话；显式开启 Confirm Email，不沿用本地默认关闭验证的配置。不自建密码表，不用 ChatGPT 账号替代。注册服务端/Auth hook 校验 18+ 声明及协议版本；声明不等于核验真实年龄 |
| PostgreSQL + RLS | 业务数据、状态机、唯一约束、事务、审计；以已验证身份和服务器管理的角色表授权，禁止用户自行修改角色/认证状态 |
| Storage | 发布后的授权媒体可公开；草稿图、发行商证明材料保持私有，用短期签名地址访问。上传需验真实格式、大小、像素、所有权并清理元信息 |
| Cron + 数据库函数 | 一个周期任务查找到期活动，执行资格冻结/开奖；另做近 30 天阅读聚合和必要清理。不开网页也执行，不依赖某台开发电脑在线 |
| 外部接口 | 仅保留游戏资料适配入口；Steam/IGDB 资质与条款未核实前人工录入。生产 SMTP 经批准后接入 |

账号保护：服务端验证会话，不能仅信任前端 Cookie 内容；业务角色不放在用户可修改的 `user_metadata`。一般读写使用当前用户上下文执行 RLS；提升权限的后台密钥只用于必要的受控服务操作，不向浏览器暴露。所有可写 API、数据库函数与 Storage 都做授权；仅隐藏按钮不算权限。

**开奖必须满足的实现约束：**

1. 所有时间存 UTC，按活动时区显示；以数据库时间判断截止，数据库拒绝截止后报名和资格字段修改。已验证邮箱、18+、地区/问卷声明及规则版本在报名时留存必要快照；资格以截止时固定数据为准，不能改用开奖时最新个人资料。延迟冻结也不能把截止后的资料变化计入。
2. 每账号每活动唯一报名；规则不变后才可开始参与。用行锁与状态检查协调报名、截止及开奖；冻结候选集合与摘要，保存可复核的抽样算法版本和随机依据。
3. 由密码学安全随机源无放回抽样，禁止 `Math.random()`/普通数据库随机排序冒充安全抽样。使用 `pgcrypto` 等成熟原语，具体抽样过程在 P3 审查与测试。
4. 每活动只允许一个最终开奖结果；候选快照/随机依据确定后重试复用。并发调用靠锁、唯一约束和事务返回同一结果，结果、中奖名额与站内通知一致提交；不依靠 Cron “只执行一次”的假设。
5. 零报名、报名少于名额、延迟任务、事务中断、重复触发都须覆盖；延期不重开、不自动增加中奖者。管理员只处理失败重试和人工发奖记录，发行商不能改中奖名单。
6. 公告使用脱敏标识；联系方式只按履约所需授权展示。日志用于审计复核，不宣称能够证明运营者绝不操纵，或证明一账号等于一真实人。Cron 为周期扫描，分钟级方案不承诺整秒开奖；停机后补跑并显示延迟。

**迁移约束：**仓库保存 SQL、RLS、函数、任务定义、环境变量名与版本锁；业务记录使用独立 UUID，文件保存对象路径而非固定主机 URL。Next.js 可部署到标准 Node.js/Docker 环境；Supabase 可自托管，但迁移 Auth、密码哈希兼容、签名密钥、存储文件与重新登录都需演练。数据库备份不包含图片实体，必须分别备份并做恢复测试。不承诺一键迁移或零停机。

## 4. 数据库主要实体

| 实体组 | 主要内容 / 关系 / 约束 |
| --- | --- |
| Auth users、profiles、user_roles、consents | Auth 管凭据；profile 管昵称/状态；角色由超级管理员维护；声明、协议版本、推荐授权和撤回独立留痕。封禁需同时阻止写入与敏感访问 |
| publishers、publisher_invitations | 所属用户、工作室信息、证明、申请/认证状态；邀请有时限并存令牌摘要；接受邀请不自动通过认证 |
| games、platforms、game_platforms | 游戏主档与多平台关联；资料来源与获取日期可追溯；允许人工维护 |
| articles、article_translations、tags | review/news 共用发布状态、作者、时间；测评关联游戏、测评平台/版本及官方分数。翻译 `(article_id, locale)` 唯一；标题/正文/黑白点按语言保存，分数和互动共享 article 身份 |
| article_view_daily、site_metrics | 按日聚合，近 30 个自然日（站点时区）每天更新；不用累计量替代。指标值、口径、更新日及维护人独立保存；高分同分按发布时间排序 |
| player_ratings、favorites、comments | 玩家对游戏评分 `(user_id, game_id)` 唯一；收藏关联文章；评论默认 pending，本人/管理员可见，approved 才公开。官方和玩家分均约束 0—10、0.5 步进；玩家分不覆盖官方分 |
| activities、activity_translations、activity_questions | recruit/giveaway、发行商 owner、审核状态与时间、地区/年龄条件、规则版本、报名问题；私有草稿到审批发布，已公开活动修改不得绕过复审/已冻结规则 |
| recruitment_applications、referrals | 报名人、活动、回答、筛选状态；原始申请仅本人和超级管理员可见；向指定发行商推荐须绑定授权范围，仅开放已授权的最少字段 |
| prizes、lottery_entries、draw_runs、draw_candidates、winners | 奖品与名额；报名 `(activity_id,user_id)` 唯一；截止候选快照；一个最终 draw；中奖用户/奖品名额有唯一约束，不允许重复占位 |
| fulfillment_records、notifications | 人工发奖状态、执行人/时间、站内通知；保留必要记录，不保存或自动派发 Steam Key |
| business_requests、business_notes、cooperation_cases | 发行商所属申请和商务状态；内部沟通默认私有；公开案例单独维护，记录公开授权 |
| assets、audit_logs、site_settings | 文件权限及素材来源/授权、审核/开奖/角色变更日志、团队/分众组/联系方式/条款版本等站点设置；日志不可由普通账号改写 |

这些是主要逻辑实体，非已建库表。内容富文本采用受控 JSON 结构，展示与链接/图片入口均校验，防止持久型 XSS。数据库级外键、唯一约束和索引随 P2/P3 迁移落地。

## 5. 角色权限矩阵

“本人/所属”均要求服务端校验 owner 与状态。所有注册角色的基础玩家操作都要满足 18+、邮箱验证和未封禁；管理角色不会绕过自己的活动参与资格。调度身份是受限系统任务，不是可登录的人类角色。

| 操作 | 游客 | 玩家 | 认证发行商 | 内容编辑 | 超级管理员 |
| --- | --- | --- | --- | --- | --- |
| 阅读已发布内容/脱敏结果 | 是 | 是 | 是 | 是 | 是 |
| 评分、收藏、评论、报名与参与 | 否 | 本人 | 本人 | 本人 | 本人 |
| 查看待审评论/个人状态 | 否 | 本人 | 本人 | 本人 | 全部 |
| 官方测评/新闻/游戏资料编辑发布 | 否 | 否 | 否 | 是 | 是 |
| 活动草稿编辑、提交 | 否 | 否 | 所属活动 | 否 | 全部 |
| 活动审批/直接发布、评论审批 | 否 | 否 | 否 | 否 | 是 |
| 原始招募申请及筛选 | 否 | 本人申请 | 否 | 否 | 全部 |
| 推荐给发行商的资料 | 否 | 本人状态 | 仅已授权推荐字段 | 否 | 按授权管理 |
| 商务申请与进度 | 否 | 否 | 所属申请 | 否 | 全部 |
| 中奖名单/发奖 | 脱敏只读 | 脱敏+本人状态 | 脱敏+所属活动必要履约信息及发奖记录 | 脱敏只读 | 管理记录；不得任意改随机结果 |
| 用户/角色/发行商认证/站点敏感设置 | 否 | 否 | 否 | 否 | 是 |

发行商的 `owner` 过滤不能代替推荐授权，编辑权限不能变成后台全权。发行商认证被撤销或角色被收回后，应立即失去相应能力，不能仅等待旧 JWT 自然过期。
